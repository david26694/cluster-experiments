    Spec: MLRATE — Machine Learning Regression-Adjusted Treatment Effect Estimator¶

    Reference: Guo et al., NeurIPS 2021 — arXiv:2106.07263

    Goal¶

    Add an MLRateHandler that implements MLRATE variance reduction: use K-fold cross-fitting on the experiment data itself (no pre-experiment data required) to produce ML-predicted outcome covariates, then feed them into the existing OLS-based analysis exactly as CUPAC does.

    Background¶

    CUPAC trains a model on pre-experiment data and predicts on experiment data. MLRATE instead uses K-fold cross-fitting on the experiment data:

    1. Split experiment rows into K folds (by cluster if cluster_cols are provided).
    2. For each fold k: train the model on the other K-1 folds, predict on fold k.
    3. Stack all fold predictions → ĝ(X_i) for every row, with no overfitting bias.
    4. Include ĝ(X_i) as a covariate in OLS: Y_i = α + τ·T_i + θ·ĝ(X_i) + ε_i.

    Cross-fitting is what makes this safe to do on experiment data: each unit's prediction comes from a model that never saw that unit. If ĝ is uninformative, θ → 0 and we recover the standard difference-in-means estimator — no harm done.

    In clustered experiments, rows from the same cluster are correlated. Standard row-level KFold would split a cluster across train and validation, leaking cluster-level signal into the predictions. The split must therefore happen at the cluster level using GroupKFold, so entire clusters land in one fold.

    Requirements¶

    R1 — MLHandler Protocol¶

    • Lives in cluster_experiments/cupac.py alongside CupacHandler and MLRateHandler.
    • Defines the shared interface for all covariate-injection handlers:
    class MLHandler(Protocol):
    @property
    def cupac_outcome_name(self) -> str: ...

    def add_covariates(
        self,
        df: pd.DataFrame,
        pre_experiment_df: Optional[pd.DataFrame] = None,
    ) -> pd.DataFrame: ...
    • CupacHandler, MLRateHandler, and NoOpHandler all satisfy this Protocol (no explicit inheritance needed — structural subtyping).
    • PowerAnalysis and NormalPowerAnalysis type-hint their handler field as MLHandler, replacing the current CupacHandler-only type.

    R2 — NoOpHandler¶

    • Lives in cluster_experiments/cupac.py.
    • Returned by PowerAnalysis when cupac_model=None.
    • add_covariates returns df unchanged; cupac_outcome_name returns "".

    R3 — MLRateHandler class¶

    • Lives in cluster_experiments/cupac.py alongside CupacHandler.
    • Satisfies the MLHandler Protocol.
    • __init__ params: ml_model (sklearn estimator), n_folds: int = 5, target_col: str = "target", features: List[str] = [], cluster_cols: Optional[List[str]] = None, random_state: Optional[int] = None.
    • add_covariates(df, pre_experiment_df=None) -> pd.DataFrame
    • Ignores pre_experiment_df (accepted only to satisfy the Protocol).
    • If cluster_cols is set: use GroupKFold(n_splits=n_folds) with groups derived from the unique combination of cluster_cols values per row.
    • If cluster_cols is None: use standard KFold(n_splits=n_folds).
    • Raises ValueError if the number of unique clusters < n_folds.
    • Adds column estimate_{target_col} (same name as CUPAC so downstream analysis code is unchanged).
    • Raises ValueError if any column in features is missing from df.

    R4 — ml_option param in PowerAnalysis¶

    • PowerAnalysis and NormalPowerAnalysis keep cupac_model: Optional[BaseEstimator] (unchanged from today) and gain two new params:
    • ml_option: str = "cupac" — "cupac" or "mlrate", selects which handler to build.
    • n_folds: int = 5 — used only when ml_option="mlrate".
    • Internally both classes build and store self.handler: MLHandler:
    • cupac_model=None → NoOpHandler()
    • cupac_model=... + ml_option="cupac" → CupacHandler(cupac_model, ...)
    • cupac_model=... + ml_option="mlrate" → MLRateHandler(cupac_model, ...)
    • from_config raises ValueError if both cupac_model and mlrate_model are non-empty in the config (mutual exclusion enforced at the config layer).
    • The covariate column name is still estimate_{target_col}, so check_covariates() needs no change.
    • PowerAnalysis automatically passes splitter.cluster_cols (if present) when constructing MLRateHandler so cluster-aware splitting is the default.
    • Backward compatibility: After setting self.handler, both classes must also set self.cupac_handler = self.handler so that any existing code accessing the old attribute name does not break.

    R5 — PowerConfig support¶

    • Add ml_option: str = "cupac" and n_folds: int = 5 fields to PowerConfig.
    • Expand cupac_model_mapping to include standard sklearn models usable by both strategies, e.g. {"": None, "mean_cupac_model": TargetAggregation, "linear": LinearRegression}. No separate mlrate_model_mapping needed — ml_option is the selector, cupac_model is the model for both strategies.
    • No mutual-exclusion check needed: ml_option unambiguously selects the strategy.
    • NormalPowerAnalysis.from_config and PowerAnalysis.from_config pass cupac_model=, ml_option=config.ml_option, and n_folds=config.n_folds.

    Note: arbitrary sklearn models (e.g. GBM) cannot be expressed as a config string — the config round-trip only covers models registered in cupac_model_mapping. Pass them directly as cupac_model=GBM() with ml_option="mlrate".

    R6 — Reproducibility¶

    • Accept random_state: Optional[int] = None in MLRateHandler.__init__ and pass it to sklearn.model_selection.KFold.
    • Note: GroupKFold is deterministic given group assignments and does not accept random_state; only pass it when using standard KFold.

    R7 — Inference pipeline (HypothesisTest / AnalysisPlan)¶

    • HypothesisTest.__init__ gains ml_option: str = "cupac" (mirrors the ml_option in PowerAnalysis).
    • The existing cupac_config: Optional[dict] is reused as the handler-kwargs dict for both strategies:
    • ml_option="cupac" (default): CupacHandler(**cupac_config) — unchanged behaviour.
    • ml_option="mlrate": MLRateHandler(**cupac_config) — keys should be ml_model, features, n_folds, etc.
    • When cupac_config is None, use NoOpHandler regardless of ml_option.
    • HypothesisTest._add_covariates calls self.handler.add_covariates(df) regardless of handler type (polymorphism via MLHandler Protocol).
    • HypothesisTest.from_config and AnalysisPlan.from_dict thread ml_option through from the config dict.
    • AnalysisPlan.from_metrics_dict (the shortcut constructor) documents that it does not support MLRATE, same as it currently does not support CUPAC.
    • Backward compatibility: After setting self.handler, HypothesisTest must also set self.cupac_handler = self.handler so that any existing code accessing the old attribute name does not break.

    R9 — Cluster-aware cross-fitting¶

    • When cluster_cols is set, group rows by their unique cluster combination before splitting: all rows belonging to the same cluster must land in the same fold.
    • Use sklearn.model_selection.GroupKFold for this.
    • Raise a clear ValueError if n_unique_clusters < n_folds, e.g.: "MLRateHandler: n_folds=5 but only 3 unique clusters found. Reduce n_folds.".
    • cluster_cols defaults to None (standard row-level KFold) so the non-clustered use case is unaffected.

    Out of Scope¶

    • MLRATE for DeltaMethodAnalysis / ratio metrics.
    • Combining MLRATE + CUPAC simultaneously.
    • Hyperparameter tuning inside MLRateHandler.
    • Docs notebook.

    Acceptance Criteria¶

    • [ ] No data leakage: predictions on each fold come from a model not trained on that fold.
    • [ ] Column added: add_covariates returns df with estimate_target column, same length as input.
    • [ ] Protocol compliance: CupacHandler, MLRateHandler, and NoOpHandler all satisfy MLHandler (verified via isinstance with runtime_checkable or static type check).
    • [ ] NoOpHandler: PowerAnalysis() with no cupac_model returns df unchanged and adds no covariate column.
    • [ ] Missing features: add_covariates raises ValueError when features columns are absent from df.
    • [ ] Cluster leakage: with cluster_cols set, no cluster appears in both train and validation of the same fold.
    • [ ] Too few clusters: add_covariates raises ValueError when n_unique_clusters < n_folds.
    • [ ] Auto cluster passthrough: PowerAnalysis with a ClusteredSplitter and ml_option="mlrate" passes cluster_cols to MLRateHandler automatically.
    • [ ] Variance reduction: on a synthetic dataset where features correlate strongly with target, MLRATE yields a smaller std error than plain OLSAnalysis.
    • [ ] No harm: with random features, std error with MLRATE is no larger than without it (within sampling noise at n=5000).
    • [ ] Config round-trip: PowerAnalysis.from_dict({"cupac_model": "linear", "ml_option": "mlrate", ...}) constructs an MLRateHandler using a model registered in cupac_model_mapping. Arbitrary sklearn objects must be passed directly as cupac_model=GBM() with ml_option="mlrate".
    • [ ] Inference pipeline — ml_option: HypothesisTest(cupac_config={...}, ml_option="mlrate") builds MLRateHandler and runs add_covariates.
    • [ ] Inference pipeline — from_dict: AnalysisPlan.from_dict threads ml_option through correctly.
